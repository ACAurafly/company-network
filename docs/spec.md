# 公司网络客户端：连接稳定性与操作入口修复

Status: ready-for-agent
Date: 2026-11-09（北京时间）
Baseline: 公司网络 1.2；Windows 10/11 x64（Intel/AMD）

## Problem Statement

员工使用“公司网络”远程办公时，遇到五类问题，影响日常协作、网页访问和连接控制。

| 问题 | 已掌握的事实 | 对员工的影响 |
| --- | --- | --- |
| 飞书频繁断连 | 用户报告，尚无本次故障的连接日志和复现数据。 | 消息和协作连续性受影响。 |
| 飞书文档打不开 | 用户截图显示 Chrome 打开飞书文档时出现 `ERR_FAILED`。 | 无法阅读工作文档。 |
| Google 等外网建立连接慢 | 用户报告网站可以打开，但建立连接的等待时间长；尚未测量各阶段耗时。 | 网页能用，但工作需要反复等待。 |
| 桌面图标重复、难以区分 | 截图有“公司网络-连接”“公司网络-断开”“公司网络-GPT”三个相似图标；源码确实创建三个独立操作入口。 | 用户需要记住不同图标的用途。 |
| 连接后应用消失，找不到断开入口 | 桌面连接入口运行连接命令后退出；当前界面没有托盘入口，也没有持续同步连接状态。 | 网络仍可能连接，但用户找不到控制窗口。 |

当前证据足以解释后两项的入口设计问题。前三项仍需在受影响环境复现，分别区分飞书连接、VPN 会话、DNS、路由、代理和网页请求阶段；不能仅凭一个浏览器错误码认定根因相同。

## Solution

员工通过一个“公司网络”入口完成连接、查看状态、打开 GPT 和断开。连接成功后窗口保持可见；用户主动收起后，可以从托盘或桌面入口找回。断开、取消连接和退出都有明确的结果反馈。

网络修复以真实业务可用为目标：飞书持续稳定，已授权文档及必要资源能够加载，外网首次建连等待缩短。同时保留已有公司内网和 GPT 访问能力。先在相同环境取得故障基线，再针对证据支持的原因修改，并用同样的员工流程验收。

本规格包含两条实施线：客户端入口及连接控制；网络复现、定位与修复。入口修复可先推进，整体验收须覆盖五项问题。

## User Stories

1. 作为远程办公员工，我希望桌面只有一个清晰的“公司网络”入口，以便知道从哪里开始使用。
2. 作为升级用户，我希望升级时合并本应用创建的旧入口，以便不用自行判断三个相似图标该保留哪个。
3. 作为升级用户，我希望已有个人账号和可复用的网络组件继续有效，以便正常升级后无需重新配置全部环境。
4. 作为首次使用的员工，我希望按提示安装组件并使用个人账号连接，以便沿用现有使用方式。
5. 作为员工，我希望连接成功后仍能看到主窗口，以便确认状态并继续操作。
6. 作为员工，我希望窗口显示当前实际连接状态，以便区分正在连接、已经连接和连接失败。
7. 作为员工，我希望收起窗口后能从托盘找到应用，以便随时管理连接。
8. 作为员工，我希望托盘提供“显示窗口”和“断开”操作，以便不用寻找安装目录。
9. 作为员工，我希望再次打开桌面入口时找回已有窗口，以便不会出现多份互相矛盾的状态或重复连接。
10. 作为不熟悉系统托盘的员工，我希望即使托盘图标被 Windows 收起，也能通过桌面入口断开，以便始终有容易找到的操作路径。
11. 作为员工，我希望关闭窗口时明确知道网络是否仍然连接，以便不会把关窗误认为断网。
12. 作为员工，我希望“断开并退出”完成后得到真实结果，以便放心结束远程访问。
13. 作为员工，我希望等待连接时可以取消，以便遇到登录取消或网络异常时及时停止。
14. 作为员工，我希望连续点击连接不会创建多份连接操作，以便不会产生状态冲突。
15. 作为员工，我希望手动断开后应用停止本次重连尝试，以便连接行为服从我的操作。
16. 作为员工，我希望断开失败时知道仍需重试，以便不会误以为远程访问已经结束。
17. 作为员工，我希望电脑休眠恢复或切换网络后状态及时更新，以便知道是否需要重新连接。
18. 作为飞书用户，我希望连接公司网络后消息和在线状态持续正常，以便连续开展工作。
19. 作为飞书用户，我希望短暂网络中断后能恢复使用或获得明确的恢复提示，以便无需反复猜测和重启软件。
20. 作为飞书文档读者，我希望从飞书客户端打开有权限的文档，以便直接进入同事分享的材料。
21. 作为飞书文档读者，我希望在默认浏览器打开同一份文档也能正常阅读，以便不同打开方式具有一致的可用性。
22. 作为飞书文档读者，我希望文档的正文、图片和必要资源一并加载，以便成功打开不只是显示一个空白页面。
23. 作为飞书用户，我希望登录过期或权限不足与网络故障能够被区分，以便采取正确的处理方式。
24. 作为外网使用者，我希望首次打开 Google 等工作网站时更快完成建连，以便减少等待。
25. 作为外网使用者，我希望后续刷新和打开页面也保持可用，以便速度优化不会增加请求失败。
26. 作为已有 GPT 用户，我希望原来的网页入口和 API 配置继续可用，以便不用迁移现有工具。
27. 作为公司内网用户，我希望修复飞书和外网问题后仍可访问已授权的公司资源，以便远程工作的主要用途保持完整。
28. 作为装有其他网络工具的员工，我希望应用在实际发生配置冲突时提供可操作的提示，以便不因图标存在就被要求卸载软件。
29. 作为员工，我希望断开后普通上网恢复到连接前的可用状态，以便远程访问结束后仍能正常办公。
30. 作为员工，我希望能够提供脱敏的故障信息，以便管理员定位问题时不需要我的密码或临时登录令牌。
31. 作为维护者，我希望区分 VPN 建立耗时与网站建连耗时，以便针对真正缓慢的阶段修复。
32. 作为维护者，我希望比较同环境修复前后的成功率、耗时和断连次数，以便根据可重复证据判断修复效果。
33. 作为维护者，我希望修复继续遵守个人认证、证书校验和配置归属限制，以便保持现有访问边界。
34. 作为维护者，我希望新装、从 1.2 升级和重复运行都经过验收，以便交付包在员工电脑上具有一致行为。

## Implementation Decisions

以下是本规格采用的实施方案；尚未完成现场复现的网络原因明确保留为待验证项。

1. **沿用现有技术与访问边界。** 在现有 C# / .NET Framework / WinForms 启动器和 SoftEther 双层连接上修改。保留外层传输、内层员工个人认证、服务器证书固定、连接与路由就绪门禁、账号身份迁移以及按归属清理配置的行为。保留 GPT 原网页入口和 API 基址，不恢复已在 1.2 取消的自动到期限制。

2. **统一桌面入口。** 新装只创建一个打开主界面的“公司网络”快捷方式；“连接”“断开”“打开 GPT”集中在界面内。升级合并本应用拥有的旧三个快捷方式，并检查目标、参数和安装归属；重复升级保持幂等。同名且归属不明的快捷方式保留并提示冲突，不仅按名称删除。桌面图标和托盘图标使用一致、可辨识的应用标识。

3. **建立常驻界面与窗口找回行为。** 同一 Windows 用户只保留一个交互主实例。再次从桌面启动时显示并激活该窗口，读取真实连接状态。连接成功不主动隐藏窗口。主动最小化可收起；连接期间点关窗收至托盘并解释连接仍保持。托盘提供状态、显示窗口、断开、打开 GPT、断开并退出；未连接时允许正常退出。即使托盘入口不可见，重新点击桌面入口也能找回窗口。

4. **统一操作与状态来源。** 让主窗口、托盘及既有命令入口共享一个应用操作控制边界，使用引擎会话和必要路由事实更新状态，而不是保留上次操作的成功文案。区分未连接、连接中、已连接、恢复中、断开中和失败；查询失败或部分断开时明确表示未确认结果。保留既有命令参数、退出码及可机器读取的结果，避免破坏维护流程。VPN 已连接与特定网站可达是两种不同结果，界面和诊断分别表达。

5. **可取消、可停止、可确认断开。** 连接操作期间保持取消能力，串行处理同一用户的连接状态变更；取消和手动断开优先于本次连接或恢复操作。沿用引擎已有恢复能力，不叠加互相竞争的重连循环。取消、失败回收及退出均检查本应用两层连接的实际结束状态；清理异常保留原因，不再无条件报告“已断开”。无法确认断开时保留控制入口并允许重试。

6. **先确认网络故障发生在哪一层。** 在受影响电脑记录实际客户端版本、发生时间、网络类型、两层会话、地址与路由、有效 DNS、系统代理及实际运行的其他网络工具；分别观察飞书断连、文档失败和外网慢建连。桌面有 Clash Verge 图标只说明存在快捷方式，不能证明代理或 TUN 正在运行。历史 Fake-IP 观测只作为排查线索，不当作当前故障结论。

7. **按复现证据选择最小网络修复。** 优先验证 DNS 返回与实际转发路径是否一致、飞书文档及依赖域名是否命中预期策略、代理与 TUN 是否争用、外层是否被错误送回内层、IPv4/IPv6 是否存在不同失败路径，以及 TCP/TLS 重试和 MTU 是否参与故障。仅对已定位的问题调整客户端适配或公司网关配置。DNS、分流和协议调整必须同时检查飞书、外网、公司内网及 GPT；不预设全局直连、全局改 DNS、关闭证书校验或更换 VPN 协议作为通用修复。

8. **分别优化两种等待。** VPN 等待从员工发起连接计到双层与必要路由就绪；网页等待从发起请求计到 HTTPS 就绪，并拆分 DNS、TCP、TLS、首字节及失败重试。针对复现的慢阶段优化。取消等待、提前显示成功或只统计成功请求均不算性能改善。

9. **提供适量的脱敏诊断。** 在当前应用内提供故障详情或导出入口，记录版本、时间、状态转换、原生错误码、相关路由/DNS/代理摘要和分段耗时。仅保留定位本次故障所需信息；导出前移除密码、认证头、Cookie、文档内容、临时登录令牌和 URL 中的敏感查询参数。导出不自动发送给其他人。

10. **交付可验证的升级包。** 更新员工说明，覆盖单入口、托盘找回、关窗与退出差异及故障信息提供方式。发布前用同一构建完成新装、从 1.2 升级、重复运行和业务回归，保留构建标识、校验值及对应证据。公司外实机与本机验证结果分别记录。

## Testing Decisions

**测试边界已经用户确认。** 2026-11-09，用户确认以 Windows 员工完整使用流程为主，覆盖飞书稳定性、文档打开、外网建连速度、窗口找回和断开；另检查安装升级只保留一个桌面入口，并复用已有自动化测试。

**好测试检查外部行为。** 从“启动、连接、打开业务、收起、找回、取消、断开、退出”等操作进入，断言实际可见状态、真实会话结果和业务访问结果。避免断言私有方法、按钮坐标或内部调用次数；网络可用性和速度需要真实链路证据，替身只用于可重复地构造状态与故障。

**优先复用现有边界，只新增一个应用级操作边界。** 既有 Core 测试覆盖外层就绪后才能建立内层、路由门禁、配置校验等；Adapter 测试覆盖网卡复用和驱动助手失败。新的操作控制边界接受系统操作结果及状态快照，让主窗口、托盘和命令入口共用；从这一层验证找回窗口、并发操作、取消、失败回收及重开后的状态恢复。安装升级作为完整使用流程的前置场景，使用隔离桌面目录验证最终快捷方式集合，不逐个扩散私有测试接口。

**已有先例与限制。** 1.2 交付记录记载 19 项 Core、5 项 Adapter 通过，并有 Windows 双层连接、GPT 原地址、Google 204 和断开对照脚本与结果。本次只是读取这些历史证据，未重新运行。历史验证缺少飞书持续使用、文档浏览器链路、分段耗时以及完整公司外实机覆盖；不能直接替代本次验收。测试执行入口与证据定位见附录。

**环境与对照。** 至少覆盖 Windows 10/11、一个新装环境、一个从 1.2 升级的环境，以及受影响员工的公司外网络或能够复现故障的等价外网。保持同设备、同账号、同目标和相近时段，对照未连接、旧版已连接、新版已连接、断开后；其他代理/TUN 的状态必须记录。Chrome 是已知报错环境，必须覆盖并记录版本；默认浏览器不同则补测该浏览器。外网直连本来不可达时，直接记录该限制，以可访问的旧版公司路径作性能对照。网络中断和冲突注入在测试环境进行。

**性能样本定义。** 固定 Google 的历史 HTTPS 探测目标；其他站点只加入已报告缓慢且具备测试条件的目标，同一目标前后使用相同 URL、请求方式及响应体处理方式。逐目标报告，不将不同网站混合计算分位数。冷请求指每次使用独立客户端且不复用 TCP 连接或 TLS 会话；DNS 缓存命中状态单独记录，并使修复前后状态一致，未控制的 DNS 样本不能称为 DNS 冷启动或混入同组比较。热请求在同一客户端中先预热，再保持相同的 DNS 缓存及连接复用条件；实际复用连接时，握手耗时记为不适用，比较从请求发起到首字节的耗时，不用零握手时间制造改善。缓存控制在隔离测试环境或专用客户端中完成，不清空公司共享 DNS 缓存。

下列采样量和时限是本规格建议的工程默认值，并非用户提供的既有 SLA。用户确认的是测试范围；如实施中需要调整默认值，应记录基线与理由，不能把未达到的门槛记为通过。

| 验收项 | 操作与通过标准 |
| --- | --- |
| 飞书稳定性 | 在稳定外网下持续使用 60 分钟，通过专用测试会话完成至少 30 次消息同步检查；没有由公司网络故障造成的意外离线或同步中断。记录飞书与两层 VPN 各自的状态，不能将飞书离线直接等同于 VPN 断开。 |
| 飞书文档 | 选择已有阅读权限的测试文档，从飞书客户端和 Chrome 各打开 10 次；默认浏览器不是 Chrome 时再补测该浏览器 10 次。正文及必要图片等资源均可加载，无 `ERR_FAILED`，记录各浏览器版本。同时检查合法的直接链接与正常登录流程；过期令牌或权限不足须归类为认证/权限结果。 |
| 网络短暂中断 | 在测试环境分别模拟短暂断网、休眠恢复和网络切换；状态在检测后及时变化，恢复可用或展示明确可执行的恢复提示。若手动断开，后续不得被旧操作重新连上；不以凭空承诺的恢复秒数代替实际观测。 |
| 外网建连速度 | 在复现慢建连的同一网络，旧版和新版对每个固定目标各采集至少 20 次冷请求、20 次热请求。按上述定义记录包含重试的 DNS/TCP/TLS 耗时、HTTPS 就绪总耗时、TTFB、p50/p95 及成功率。默认改善目标：新版冷请求 HTTPS 就绪 p95 比旧版降低至少 30%，热请求从发起到首字节的 p95 劣化不超过 10%，每组请求均成功。没有复现或没有可比基线时，该性能项记为未验收。 |
| 单入口与升级 | 新装、1.2 升级、再次运行升级后，各有且仅有一个归属本应用的桌面入口；旧三个自有入口合并。非本应用快捷方式不受影响，同名冲突可识别；个人账号、组件复用及 GPT 配置继续有效。 |
| 窗口与托盘 | 连接成功保持窗口可见；主动收起、关窗、托盘图标位于隐藏区后，都能再次从桌面找回同一主窗口。主窗口与托盘状态一致，均可发起断开；不能靠结束后台进程才能停止访问。 |
| 取消、断开和退出 | 连接、恢复和已连接三种状态均覆盖取消/断开；用户操作 5 秒内有明确进度反馈，10 秒内完成或显示仍未完成及原因。只有确认两层结束才显示已断开或完成“断开并退出”。模拟一层断开失败时保持失败信息及重试入口。 |
| 业务与访问边界回归 | 原 GPT 网页及 API 完成代表性真实请求，已授权内网资源可达，既有公司网站分流保持预期。错误凭据或证书不应绕过校验；外层单独连接不能取得内层权限。断开后本应用两层会话结束，经它提供的路径被撤销；直接处于公司局域网的资源仍可能可达，须区分路径来源。普通上网与连接前对照一致。 |
| 重复操作和诊断 | 连续启动、重复连接、旧命令入口与窗口操作交错时，状态一致且无额外主窗口或遗留连接。脱敏诊断可以关联同次故障的阶段与错误，检查导出内容不含密码、认证信息或截图中的登录令牌。 |

## Out of Scope

- 新增 macOS、Linux、移动端或 Windows ARM 客户端，以及重写整个客户端或更换 VPN 架构。
- 新增账号注册、付费订阅、集中终端管控、全量监控平台或新的自动到期策略。
- 修改飞书服务本身、文档权限、员工账号策略，或把过期登录链接认定为网络修复范围。
- 为缩短建连而承诺所有外网网站的可达性、吞吐量提升或任意网络条件下的固定延迟。
- 仅凭图标存在卸载其他网络软件，批量删除不属于本应用的快捷方式，或无证据变更全公司 DNS、代理及访问策略。
- 本次规格编写期间实施生产配置变更、发布新安装包或向员工发送通知；这些均不是本次已完成成果。
