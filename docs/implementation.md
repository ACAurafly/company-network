## 打包与最终验收

[`tools/package_release.py`](../tools/package_release.py) 接受明确的 EXE、源码仓库、公开 payload 和新输出目录，生成员工 ZIP、可构建源码 ZIP、SHA256 与验证摘要。源码按 Git 跟踪清单收集，并限制目录和扩展名；载荷只允许固定的 11 项。脚本核验 EXE 版本、内嵌载荷对应关系和 ZIP 完整性，记录 Git HEAD、工作区修改标记及逐文件哈希。调用方法、部署和回滚见 [README](../README.md)。

验证摘要只记录本次打包实际执行的检查，业务验收默认 pending。维护者必须以最终构建补录以下证据：新装/升级/重复升级和个人配置复用；各连接状态下 × 即时关闭及桌面/托盘重开；取消、真实断开和失败可重试；公司内网、GPT 真实请求及断开后普通上网；飞书授权文档、60 分钟消息和外网新旧性能对照。没有同环境可比数据时，性能项保持未验收。

发布工具不安装客户端、不改变当前桌面或网络、不上传 Release，也不覆盖旧交付目录。原始 1.2 包保留，正式发布须从父任务审阅后的同一源码重新构建、复验并打包。

交付子任务已在独立工作区实际自检：员工 ZIP 4 项、源码 ZIP 35 项；载荷 11 项、EXE 版本及内嵌载荷一致性、两层 ZIP CRC/成员哈希和外部 SHA256 清单均通过。相同输入连续生成的全部产物逐字节一致，已有输出目录被拒绝覆盖。源码 ZIP 解压后使用随包载荷重新编译成功。该自检仅证明打包与源码构建闭合，未进行安装或业务操作；产物保存在忽略的 `build/` 目录，最终发布仍须重新构建验收。
