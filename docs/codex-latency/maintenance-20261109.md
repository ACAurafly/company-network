# Codex 延迟优化实施与验收

2026-11-09，北京时间。**已修正本机 Codex 的 WS 能力声明，并验证新启动的同版本 Codex 使用 HTTP 完成真实任务。** 四项维护工具已进入同一实现分支。员工并发试点、公司外 VPN、原业务聊天续跑尚未验收；桌面进程未重启，新进程验证不代表所有已有会话都已刷新。

| 项目 | 实施与结果 |
| --- | --- |
| 协议修复 | 公司 provider 应用时仅将 WS 能力声明由 true 改为 false，独立字节比对通过；入口、认证和当时的模型/effort均未由该工具改动。私有备份及冲突检查支持回滚。5 个真实独立新会话全部正确完成。 |
| 统一采样 | 使用桌面相同 core 0.167.0-alpha.3.2 的 app-server 流事件，记录首可渲染文本、结束、工具、失败、用量和关联 ID；不保存原始配置、正文或 stderr。 |
| 真实请求关联 | 5 个协议会话、30 个正式对照会话、12 个受控并发会话共 47 个临时会话，对应 87 条网关转发记录；均为 HTTP POST/200、openai_ws_mode=false，全部与会话及访问日志精确关联。 |
| 并发受控验证 | 专用普通测试用户在限额1、2下各完成3组双路任务，共12个正确结果。限额1时Redis记录一个执行、一个等待且转发区间串行；限额2时记录两个执行、无观测到等待，三组转发重叠约2.60、3.12、3.09秒。 |
| 413恢复入口 | 15条当前数据库413记录精确关联到同一非网络业务长聊天，最近失败为remote compact超限。管理员私有目录已保存1182字节精简交接，新临时会话接收并正常完成；这只验收交接接收，未续跑原业务、改原聊天或自动化。 |
| VPN准备 | 比较工具、来源绑定、缺证据拒绝及操作说明完成；本机Google辅助探测20次独立连接、20次复用连接全部成功。真实外部网络样本为0，远程业务明确未验收。 |

同任务推理筛查为三类冻结任务、两档 effort，每类每档5个样本，共30个任务、50轮，质量检查全部通过。下表为**该次任务从首轮提交到末轮完成**的中位数，不含app-server初始化；小样本只作描述。

| 任务 | max | medium |
| --- | ---: | ---: |
| 固定短答 | 10.04秒 | 8.33秒 |
| 读取夹具并计算 | 17.31秒 | 14.09秒 |
| 三轮工具上下文 | 24.61秒 | 52.96秒 |

本轮结果方向不一致，未改全局推理档位，也不承诺统一加速倍数。三类prompt均不提供待计算或待记忆的答案，预期结果留在本地断言。冻结任务manifest为 `445e55a3ed23e8e9b34d494c87491663ab82a812ab1e04995354c5ff5500e967`，每份正式报告记录采样器源码与夹具哈希。

收尾配置读到默认模型已变为 gpt-6-astra / max，WS=false仍保留，本实现没有恢复先前模型选择。上述对照全部固定使用 gpt-6.1-sol，不能外推为 Astra 的实测结果。并发编辑后，整份旧配置备份不能直接覆盖当前选择；回滚工具会拒绝这种冲突。

并发基线覆盖310秒，峰值占用3/20，最坏余量17。NAS时钟经五次往返测得比客户端快约2.597秒，最低往返估算不确定度约14毫秒；保留原始记录，并另存校正后的统一时间线。容量结果为**采集时刻的历史复核**：容量评估与受控验证通过，不能拿作之后时刻的生产准入。两名员工的限额仍为1；首位试点用户在最近30分钟无业务请求，缺少规格要求的代表性负载，未跳过用户5→2的试点顺序。

转发区间按网关Forward耗时及访问日志结束时刻重建，另用100毫秒粒度Redis名额与等待计数交叉核对，不能据此声称上游模型内部并行。微小等待可能低于采样粒度。端到端首可渲染文本、网关首语义事件和转发处理时间分别报告。

临时测试key、一天订阅和测试用户均通过支持的管理/用户API撤销或删除并回读验证；私有测试凭据文件已删除。既有员工、管理员和上游账号配置未调整。只保留受控位置的客户端回滚备份及恢复交接。

双轴代码审阅的Standards轴1项、Spec轴3项中，重复项合并后共3个独立问题已修复：新版采样格式与VPN消费者的合同、客户端断流回滚、受控/生产试点时序。新增真实producer→consumer离线合同与异常回归，54项Python工具测试通过；客户端原76项Core/Adapter/Lifecycle/Diagnostics检查也通过。没有修改员工程序源代码或原始发布包。

桌面进程没有在本次任务中重启；新启动的同版本core已实测读取新配置。结束当前工作后可重启Codex，使桌面后续请求载入这项配置；不能把新进程验证写成已有桌面所有会话都已刷新。
