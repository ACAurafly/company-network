# 统一 Codex 计时并对照 effort 与会话整理

Status: ready-for-agent

执行状态：采样工具和交接文档已实现，离线测试通过；现场effort对照、多轮协议及413具体会话恢复待主对话验收。原全局默认未修改。

依赖：[01 协议对齐](01-align-client-transport.md)；[总规格](../spec.md)。

目标：让首可见输出、任务完成、网关转发和重试等待可比较，给出日常推理强度建议，并为已报 413 的会话提供恢复办法。

实施范围：复用现有日志提取、访问日志关联、用量汇总和 HTTPS 分段，缺失时只补一个统一采集适配层。固定同一已安装 Codex 运行版本和模型，在隔离配置比较 max/medium，原全局默认不自动改变。只读关联 413 到受影响会话；找到后以简短交接开展新会话，不复制全量历史或抬高正文限制。

验收：

- 用户全程、首可见内容、网关首语义事件和单次转发时间分别标注口径；未知阶段为空，不用推算伪造测量。
- 采集保留请求失败、重试和取消；新解析逻辑以脱敏夹具验证事件缺失、关联失败和统计分母，避免只测实现细节。
- 至少 5 对同任务交错对照，固定版本、模型、工具及出口，记录输入、缓存、输出、质量、成功率和全部耗时。区分暖启动和首次连接；小样本只给描述结论。
- 每个已定位的 413 会话交接后能完成原未完成目标且无再次超限；未能定位的记录保留为缺口，不宣称已恢复。
- 给出建议及证据强度，不将 31.9/9.8 秒的既有组间差异当作降档收益。
- 采样前冻结固定格式、文本计算、多轮工具三类夹具及预期检查点；质量检查全部通过才讨论该类速度。五对筛查只给描述性结论，方向或质量冲突时不作统一档位建议。
- 每个任务保存会话、请求/尝试关联及提交和结束事件；首可见事件缺失时该指标未验收。会话交接没有同目标原会话基线时，只验收恢复能力。

停止条件：达到明确对照结果后结束，不默认扩大负载；对照不确定时说明需要补充的具体样本。超大正文重放仅限隔离环境或脱敏事件，不发往生产。
