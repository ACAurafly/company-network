# 对照公司内与公司外 VPN 的 Codex 等待

Status: needs-info

执行状态：比较工具、附证流程与离线验证已完成；公司外真实测试结果尚不存在，远程业务未验收。协议已由工单 01 修正，公司内可复用统一采样适配器；不据此声明远程问题已修复。

依赖：[01 协议对齐](01-align-client-transport.md)、[02 统一采样与对照](02-benchmark-and-session-recovery.md)；[总规格](../spec.md)。

目标：用真实 Codex 任务说明双层 VPN、局域网接入和海外出口各自的等待，决定是否需要继续网络优化。

实施范围：沿用已部署的 SoftEther 双层接入、证书固定、现有海外出口和精确 VPN 入口 DIRECT 规则。公司内及公司外测试分别固定设备条件、Codex 版本、账号、任务、effort 和出口，并记录差异；跨不同设备时列明限制。只操作专用测试会话，不中断员工使用。

验收：

- 分别记录 VPN 就绪、到 NAS 的连接、上游网络探测、Codex 首可见输出及完成结果，保留失败和所有重试。
- 网络子项沿用每目标至少 20 次独立连接与 20 次复用连接的既有约定，记录 DNS 缓存未知及连接复用事实；不将网站探测当成模型任务完成。
- 同类真实 Codex 任务使用已统一的采样方式，至少进行 5 对配对筛查；小样本只给描述结果，有未解决差异才扩大采样。
- 分开报告公司内与公司外结果、版本及上下文差异。没有公司外设备时完成探测准备和本地验证，并明确保留远程业务未验收状态。
- 按瓶颈阶段提出下一步，不仅凭一秒级无鉴权 GET 或 NAS 健康接口判断 VPN、上游或整条链路已达标。
- 优先同设备、同账号在 15 分钟内交错取样；跨设备或长时段比较列明可比性限制。VPN 侧独有失败、至少三对同一接入阶段变慢或任务差异无法解释时，才扩大针对性复测。
- 小样本发现与网络变更建议分别交付；只有重复问题定位到具体网络阶段并形成可恢复候选时，才提出变更，不根据一次差异改网。

边界：不清共享 DNS/Fake-IP 缓存，不扩大 DIRECT 规则，不关闭证书验证，不恢复此前暂缓的同事飞书问题调查。
